## 1. 实验目标与分工

本实验在物理内存管理基础上建立Trap的保存、分发、处理与返回路径，验证异常后的继续执行及持续时钟中断。国峻赫负责初始化迁移和Trap汇编，陈铭宇负责Best-Fit必要迁移及中断异常处理，尚文轩负责独立补充测试、联合验收与报告整合。默认保持First-Fit，不迁入Lab2的Buddy或SLUB。

被测核心代码由国峻赫、陈铭宇完成，尚文轩的测试基于 `f475900` 的内核；测试及证据提交为 `2aeec0f`，源码哈希见 [验收清单](../logs/c-runs/20261029-034244/manifest.log)。文档提交不会改变被测内核。各环境地址与页数以对应构建为准。

## 2. Trap完整路径

```text
硬件设置sepc/scause/stval及sstatus，跳至stvec
  → __alltraps → SAVE_ALL → a0=sp → trap(tf)
  → trap_dispatch → interrupt_handler / exception_handler
  → __trapret → RESTORE_ALL → sret → 恢复执行
```

RISC-V硬件不替软件把全部通用寄存器压栈。硬件记录返回位置、原因和状态，汇编入口再建立内存中的TrapFrame。当前stvec采用统一入口，原因分发由C函数完成。

同步异常与当前指令相关；中断来自异步事件。处理器保存的sepc是返回依据，不能对所有Trap无条件加4：本实验可跳过的断点和非法指令按长度推进，时钟分支保持EPC。真实页故障通常需要修复后重试，不属于当前跳过策略。

## 3. 初始化与上下文保存恢复

### 3.1 物理内存迁移

page_init从DTB获得范围，检查边界，将Page数组放在内核末端后的对齐区域，先保留全部页，再登记元数据末端之后的完整空闲页。npage是页号上界，描述符数量为npage-nbase。联合基础构建128MiB对应32768个描述符，每个40字节，数组共1310720字节，空闲31928页。

保留Lab3已有PMM中断保护包装。local_intr_save记录原SIE，操作管理器期间关闭本地中断，恢复时仅在原先开启的情况下重新开启；它不提供多核互斥。

### 3.2 TrapFrame布局与返回

教师SAVE_ALL保存32个通用寄存器槽位及status、epc、badvaddr、cause，共36×8=288字节，保持16字节栈对齐。原sp经sscratch暂存后写入第2槽；a0传递当前帧地址，处理函数可以修改帧中的返回EPC。

RESTORE_ALL先取返回用sstatus和sepc，再恢复通用寄存器，最后加载原sp，避免提前失去帧基址。cause和badvaddr作为诊断快照，不机械写回。sret根据SPP恢复特权级，并按SPIE恢复SIE；当前实验从S模式进入并返回S模式，不是每次返回用户态。普通ret不能替代sret完成这些控制状态变化。

### 3.3 GDB证据

国峻赫在实际版本 `7b6c636` 上观察真实S时钟Trap：stvec与__alltraps均为0xffffffffc0200bec，scause为0x8000000000000005，a0=sp=tf=0xffffffffc0205ed0，原sp=0xffffffffc0205ff0，差值288。保存和恢复的sp、ra、t0、a0及返回CSR比较符合预期；时钟不改变EPC，sret后PC为0xffffffffc020009c。

该观察覆盖一次真实时钟及代表性寄存器，不声称手工穷举全部上下文。详见 [国峻赫章节](../parts/a-trap-entry.md)、[被测提交](../logs/a-integrated-commit.log)、[GDB日志](../logs/a-trap-debug.log)。

## 4. 中断与异常处理

interrupt_handler先去除cause最高位中断标志，再按原因分类。S时钟分支重设下一次事件、ticks递增一次，每100次输出100 ticks。当前SHUTDOWN_AFTER为10次统计，即1000 ticks后调用SBI关机；这是小组实现选择，现有材料没有规定具体阈值。每行100 ticks是区间统计，不表示ticks总值一直为100。

exception_handler对非法指令和断点输出原因及地址，再读取故障指令低16位：低两位不为11时推进2，否则对本实验32位编码推进4。该策略限定于可读取的16/32位测试指令，不是任意长指令解码器。未覆盖异常打印帧并返回诊断；未知中断同样打印原因与帧，不读取无效EPC。

Best-Fit只迁移必要状态及操作，保留教师检查，.check使用best_fit_check，避免引入Lab2独立测试依赖。默认仍First-Fit，Best-Fit在临时副本单独运行。完整设计见 [陈铭宇章节](../parts/b-trap-handlers.md)。

### 5.4 自主探索：用户态与权限保护（非本届要求）

2026-10-30补充独立用户态实验，正式默认入口保持不变。扩展页表保留原高地址S态映射，低地址0x1000映射用户代码（U/R/X，禁止写），0x2000映射用户栈（U/R/W，无执行权限），栈顶0x3000。用户代码和栈分别占独立对齐页，不把整个内核大页设置为U可访问。

S态通过sret进入U态。扩展向量用sscratch交换到保存的内核栈，建立同布局288字节帧，调用专用处理器；恢复后再次sret返回U。第一次ecall返回a0=0x567，U代码实际读写栈，并尝试读取sstatus、读取内核起点、写入用户代码页。处理器依次检查异常原因2、13、15及对应访存地址，跳过三条明确为32位的测试指令。第二次ecall检查返回值、栈内容和全部负例计数，再设置SPP及返回位置，回到原S态调用点。

扩展结束恢复satp、stvec、sscratch、sie、sstatus，并刷新地址转换缓存。两种PMM均通过上述断言，并继续通过原异常、SIE和1000 ticks关机回归。见 [First-Fit](../logs/c-runs/20261030-093858/default-run.log)、[Best-Fit](../logs/c-runs/20261030-093858/best_fit-run.log)、[源码清单](../logs/c-runs/20261030-093858/manifest.log) 与 [扩展规格](../prompts/c-user-challenge.md)。

后续质量复核还实际跳转至用户栈，捕获原因12的取指页故障，核对sepc/stval均为0x2000，并返回预设用户标签。处理器同时断言TrapFrame位于原内核sp减288的位置，最终检查原satp/stvec/sscratch/sie/sstatus全部恢复。因此栈NX、内核栈切换和状态恢复均有运行断言，而不仅是页表配置。

### 6.1 手册思考：stvec模式及兼容性

stvec低两位为MODE，其余位保存四字节对齐的BASE。Direct模式下，中断和同步异常均从BASE进入；Vectored模式下，同步异常仍从BASE进入，异步中断跳至BASE+4×cause。不应把同步异常也按原因编号偏移。当前框架把四字节对齐的__alltraps地址直接写入stvec，低位为00，因此采用Direct，由软件读取scause分发。

使用地址原本因对齐而恒为零的低两位编码模式，保持旧的对齐入口地址数值不变、继续表示Direct，是新规范兼容旧软件配置的关键。它不意味着旧硬件必然支持新Vectored模式；实际软件还应考虑硬件支持及额外对齐约束。

为进一步验证本节扩展，另实现显式 `--vectors` 实验：256字节对齐的表禁用压缩，每槽一条4字节跳转。真实断点命中BASE路径一次；设置SSIP触发S软件中断，命中BASE+4路径一次，入口清除SSIP防止重复。两路探针保留临时寄存器后进入教师__alltraps，测试后恢复原stvec和中断状态，继续正常时钟回归。两种PMM均通过 [完整扩展运行](../logs/c-runs/20261030-095832/default-run.log)。该路由探针限定S源、无嵌套，不替代通用向量入口。

### 6.2 手册思考：do-while(0)与中断保护

多语句宏使用 `do { ... } while (0)`，可在调用后加分号并作为一条语句用于if/else，避免多语句宏只有首句受条件控制、或额外分号破坏else匹配。条件恒零，所以宏体只执行一次；块内局部变量也有独立作用域。该写法本身不提供原子性，真正屏蔽中断的是宏体调用的intr_disable，恢复依赖保存的原SIE。

### 6.3 与原理课程的对应及未覆盖机制

TrapFrame的保存恢复对应CPU上下文保护，但并不等于完成进程切换：本实验没有选择另一进程或独立地址空间。时钟中断提供抢占时机，但没有实现时间片调度器。局部关中断保护单核临界区，与多核锁及原子读改写的适用范围不同。异常分发和权限恢复体现硬件/软件协作；页故障按需分配、系统调用参数校验、进程生命周期及设备驱动请求队列则尚未实现。
