## 1. 场景与输入

在 RISC-V ucore Lab2 中新增 Buddy System。已有 A 的 `page_init()`、B 的 Best-Fit，源码在仓库根目录。阅读 `pmm.h`、`memlayout.h`、`list.h`、`default_pmm.c` 及当前实现，复用 `pmm_manager` 接口，不替换教师框架。工具链通过 `source ~/OSopt/env.sh` 激活。

## 2. 目标与输出

实现 `kern/mm/buddy_pmm.c/.h`：初始化、登记可用物理页区间、分配、释放、空闲页计数及自检。提供按阶链表、伙伴判断、拆分和逐级合并。保留默认 Best-Fit，用 `PMM_BUDDY` 编译宏选择 Buddy，并给出清理后切换方法。

## 3. 约束与契约

- 阶数 0..15，块大小为 1..32768 页；每页 4096 字节。
- 以绝对物理页号计算 `buddy_ppn = ppn ^ (1UL << order)`，验证登记边界及同阶空闲块头，不能仅凭相邻且同大小合并。
- 不对齐、非 2 的幂初始区间必须完整分解，不丢尾页；多个登记区可在合法伙伴边界合并。
- 非 2 的幂请求向上取整。块头保留原请求 n，`free_pages(base, n)` 只接受原始块头和原始 n；不支持部分释放、重复释放或传入取整后的页数。
- 空闲头 `property` 记录实际块页数，分配头记录原始 n；私有 flags 第 2 位记录已分配块头。引用计数保持框架语义，释放前必须为 0。
- 不改 `struct Page`、`pmm_manager`、A 的初始化、B 的实现和教师检查，不改公共 Makefile、评分逻辑或 OSopt 包装器。
- 分配失败不改变状态。超最大阶和 SIZE_MAX 请求直接失败，零页按框架契约断言。
- 单核启动阶段使用，无锁；后续并发使用需外部串行化。

## 本轮关键反馈与修正

1. 首次运行在 `verify_state` 的 `total == nr_free_pages()` 失败，GDB 栈定位至第一个隔离测试的拆分检查，链表统计为 127、计数为 63。
2. 原因：隔离测试复用真实描述符，初始化时把测试区外、仍属于主状态的空闲伙伴误并进来。修正：每个管理状态记录登记页号上下界，伙伴查找先检查当前状态边界。修复后全部测试通过。
3. 验证脚本最初使用了与 B 输出不符的字符串，已核对并改用 `[Best-Fit behavior] ALL PASS`；没有改动 B 的测试。
4. 普通 `make grade` 在本机得到 `no $qemu_out`。本地 OpenSBI 半主机输出使用宿主 stdout/stderr，新增评分专用转接脚本，把两者送入评分请求的输出文件；不修改评分脚本或既有包装器。
