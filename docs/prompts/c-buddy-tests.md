# C：Buddy 测试规格与提示词记录

负责人：尚文轩，2412456。日期：2026-10-19。

这份测试规格与实现规格分开保存。它由助手在同一会话整理，用于测试设计和最终覆盖复核，不是用户逐字输入或另一个模型的对话记录；整理时间在初次编码之后。用户的实际授权、来源边界见 [实现记录](c-buddy.md)。

## 1. 场景与输入

被测实现是本轮新增的 `buddy_pmm_manager`。分配 n 页占用向上取整至 2 的幂的完整块；释放必须使用原始 n 和原始块头。不能套用 Best-Fit 的部分释放测试。测试使用真实 `pages[]` 和物理页号，不以虚构数组代替真实初始化。

## 2. 目标与输出

在管理器 `.check` 中运行可复现断言测试。先从真实分配器申请对齐 64 页作为测试区，暂存主状态，通过独立测试状态组织这 64 页；测试完成后清除测试元数据，将整个区间作为原分配块返回主状态。输出每组 PASS 和前后空闲页数。

## 3. 约束与覆盖

- 六级拆分：单页请求后 0..5 阶各留一个块，释放后恢复 6 阶块。
- 请求 1/2/3/4/5/8/9/16/17/32/33/64 页，检查返回块、取整占用、物理对齐和释放恢复。
- 分配全部 64 个单页并检验唯一性；释放偏移 1 和 2，证明相邻不代表伙伴；碎片状态总空闲足够但 2 页请求应失败。
- 释放所有偶数页制造碎片，再释放奇数页，检验多级合并及状态恢复。
- 对齐块内从偏移 3 登记 37 页，再登记偏移 48 的 8 页及偏移 40 的 8 页。逐页耗尽，精确核对可分配集合为偏移 [3,56)，无重复、越界和漏页，反序释放恢复 53 页。
- 用固定种子 2412456 做 1024 次混合申请/释放，以独立的逐页占用表检查重叠、对齐、实际空闲总数，并验证失败时确无足够的对齐空块。
- 每阶段检查链表双向关系、各阶块大小、对齐、保留位、块内状态、可合并伙伴已合并、空闲总数；完整主状态测试前后均核对。
- 零请求、错误释放等预期 panic 不混入正常自检；不声称已实际运行这些破坏性负例。

## 4. 验收与证据

执行 `source ~/OSopt/env.sh && python3 tools/check-buddy.py`。必须检查实际 QEMU 输出里的全部标记、无 panic、状态恢复以及默认 Best-Fit 行为通过。教师评分只对默认 Best-Fit 运行，不将其 20/20 说成 Buddy 的评分。

脚本每种模式先 `make clean` 再构建，保存 HEAD 和源码 SHA256。8 秒后结束故意空转的内核，仅终止本次启动的进程组。脚本异常退出时先读对应日志，不能把 timeout 当作测试通过。
