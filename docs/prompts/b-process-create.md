## 整理后的 spec（不是原始聊天原文）

2. alloc_proc 清零所有字段，UNINIT、PID=-1、物理根页表地址和自环链表节点正确。
3. idle=PID0/启动栈/current，不入普通链表和哈希；init=PID1/独立两页栈/parent=idle。

6. do_fork 在资源完整后登记及唤醒；失败释放已得资源，返回真实错误；保存和恢复进入时本地中断状态。

## 实际问题及处理

- 正式构建链接失败：cpu_idle 由 C 负责且尚未实现。因此记录真实失败，在全新临时副本内用会 panic 的测试桩补齐链接依赖，并绕开首次调度；不把隔离构建当成正式构建通过。
- Windows Python 无 PDF 解析库：读取课程材料时改用 WSL 已安装的 pdftotext，没有安装新依赖。
- WSL 在受限读取中被拒绝：通过获准的 WSL 调用执行工具；编译环境使用 Lab3 已验证的 GCC/GDB/QEMU 路径。
- 故障注入不能冒充真实资源耗尽：同时增加真实逐页占用所有空闲物理页的栈分配失败检查。为避免连续空闲区假设，测试使用逐页分配和归还。
- copy_mm 本阶段正常不会分配或失败：将其失败测试明确标为临时包装器合成故障，用于检查 do_fork 的未来错误传播和栈回收分支。
- 本阶段没有出现并修复六函数运行失败；首次独立运行通过。不能据此编造“先失败后修复”的代码 bug。
- 编译中的已有警告和教师调度测试函数指针类型警告保留到原始日志；没有修改教师测试。
