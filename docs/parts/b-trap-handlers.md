## 1. 范围与完整执行流

本实验是 RISC-V 中断与异常处理。A 已完成内存初始化迁移、`RESTORE_ALL` 和 `__alltraps` 调用 C 的实现。B 完成 Best-Fit 必要迁移，以及 `interrupt_handler()`、`exception_handler()`。B 本轮没有修改 A 的 `pmm.c`、`trapentry.S`，也没有修改 `trap.h`、公共 `Makefile`、`init.c` 或教师测试。

执行流为：硬件产生 Trap，进入 `stvec` 指向的 `__alltraps`；教师 `SAVE_ALL` 保存 36 个 RV64 槽位，共 288 字节；A 通过 `a0=sp` 调用 `trap(tf)`；原有 `trap_dispatch()` 按 `cause` 最高位分发；B 完成处理，必要时调整帧中的 EPC；A 恢复寄存器、`sstatus` 和处理后的 `sepc`，最后通过 `sret` 返回。当前基本实验在 S 模式运行，不能把每次返回都解释为进入用户态。

## 3. 中断处理

`interrupt_handler()` 清除 `cause` 的最高位中断标志，再按框架定义的原因码分类。即使教师直接传入不带最高位的原因 15，也能进入未知中断分支。

S 模式时钟分支依次执行：

1. `clock_set_next_event()` 设置下一次事件，维持连续时钟。
2. `ticks++`，每次调用只递增一次。
3. 当 `ticks % TICK_NUM == 0` 时，调用原有 `print_ticks()`，每次输出 `100 ticks`。
4. 当 `ticks / TICK_NUM >= SHUTDOWN_AFTER` 时调用 `sbi_shutdown()`。

时钟分支不修改 EPC。其他已知软件、时钟和外部中断输出类型；未知中断输出 `Unknown interrupt: cause ...` 并打印完整帧。这些提示分支并未实现完整的设备中断确认或驱动服务。

**关机值来源：** 课程 PDF 提到 `SHUTDOWN_AFTER`，附件源码和已提供 PDF 未给出数值。本轮用户明确确认暂按输出 10 次后关机，因此本实现默认值为 10，即 1000 ticks。该值属于本轮确认的实现选择，不能写为教师指定值。它晚于教师持续时钟测试需要的 200 ticks。

## 4. 异常处理

`exception_handler()` 对非法指令输出 `Illegal instruction at ...`，对断点输出 `Breakpoint at ...`。只有这两个分支读取 EPC 处的首个 16 位指令半字：最低两位不是 `11` 时按 2 字节推进，是 `11` 时按本实验的 32 位指令推进 4 字节。

未覆盖的异常仅调用 `print_trapframe()` 并返回，不读取 EPC 对应的指令，不伪造恢复行为。教师兜底测试构造了 EPC 为零、原因码为 20 的帧，因而不能在分类前统一解引用 EPC。

该恢复规则覆盖本实验涉及的可读取的 16/32 位断点和非法指令；没有实现任意更长指令、取指访问失败、页故障修复、系统调用分发或进程终止机制。未处理异常可能在返回后再次发生，诊断输出不代表能够自动恢复。

## 7. 问题、定位与修正

- Best-Fit 首次强制构建出现约 11 毫秒的依赖文件时间戳警告。仅删除本轮目标文件后重新编译，退出码 0 且无该警告；两次原始结果均保留在模块日志。
- 自动化环境核对曾受 PowerShell 管道 BOM、跨 shell 引号及包含空格的 PATH 影响。最终使用 UTF-8 无 BOM 管道，或直接通过 WSL `env` 传入工具路径。该问题属于命令传递，不属于内核代码故障。
- 本轮核心处理实现首次完整构建、普通启动和教师评分均通过；没有观察到需要修改教师测试或 A 汇编才能解决的内核错误，不编造额外 Bug 经历。

## 8. 与 OS 原理的对应和边界

TrapFrame 体现中断现场保存，原因码分发体现统一入口与具体处理策略的分离，EPC 更新决定异常返回位置；时钟重设体现周期事件由连续单次事件维持。物理页管理包装展示临界区中保存、关闭和恢复中断状态，不能无条件恢复为开启。

本实验以单核内核 S 模式路径为主，没有实现进程调度、多核同步、完整设备驱动、用户态切换和系统调用、虚拟内存异常修复等完整 OS 功能。中断关闭也不能替代多核锁。
