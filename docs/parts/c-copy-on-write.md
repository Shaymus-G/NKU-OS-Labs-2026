# Challenge 1　写时复制

尚文轩（2412456）

## 权限与页引用

普通 `fork` 默认创建独立 VMA 和页表。对原本可写的用户页，子进程先共享旧物理页，将 PTE 改为 `W=0, COW=1`，其中 `COW` 使用 Sv39 RSW 的一位。只有子进程所有映射都建好后，父页表才统一撤销相应的写权限并刷新 TLB。任何分配失败均发生在父权限提交之前，清理子地址空间后，父 PTE 及页引用恢复到 fork 前的状态。原生只读代码或数据可共享，并保留原权限。

| PTE 状态 | 事件 | 转移 |
| --- | --- | --- |
| 私有可写 | 普通 `fork` 成功 | 父子都指向旧物理页，置 `COW`、清 `W`，页引用增加 |
| COW，只读，多引用 | 另一进程继续 `fork` | 子仍使用同一物理页，增加一个引用 |
| COW，只读，多引用 | 用户写或内核向该地址写回 | 分配、复制一页，将写方转成私有可写，旧页引用减一 |
| COW，只读，单引用 | 写入 | 当前物理页原地恢复写权限，清除 `COW`，无需分配 |
| COW，只读，多引用 | 写入需要新页但分配失败 | PTE 和引用保持；用户异常交给退出路径，`wait` 输出失败时保留僵尸供重试 |
| 原生只读或无映射 | 写入 | 权限检查拒绝；只读权限和栈空洞保持 |
| 任一有效映射 | 退出或解除映射 | 减少引用，最后一个引用消失时归还物理页 |

## 触发路径

U 态 store page fault 通过 `tval` 定位虚拟地址，`resolve_cow_write()` 在 `mm_lock` 下同时检查 VMA 的写权限与叶 PTE，必要时复制并更新映射。成功时保留 `sepc`，让 `sret` 后重试原 store。用户系统调用的 `ecall` 则前移 `sepc` 四字节。

`do_wait()` 通过内核别名写退出码，硬件不会替这条内核写检查用户页表的 W 位。已有的 `proc_mem_copy()` 因此先检查整个目标范围，再逐页完成 COW，最后复制字节。跨页输出缓冲区也遵守同一规则。

## 与 Dirty COW 的关系

历史 Dirty COW 涉及 Linux 对私有文件映射的写权限判断与并发内存管理操作失去一致性，导致写入落到仍共享的文件后备页。生产内核需在页表遍历、引用持有、权限复核及失效操作之间建立并发同步。[Red Hat CVE-2016-5195 公告](https://access.redhat.com/security/cve/cve-2016-5195)

Lab5 用匿名物理页保存已装载的数据，由单 hart、`mm_lock` 和页引用计数协调映射更新。由于缺少 Linux 的文件页缓存和用户页固定接口，这里验证的是原生只读映射、先完成 COW 再写入、分配失败时保留原映射，以及最后引用释放等条件。

复现与原始证据见 [C 交接与测试索引](../notes/lab5-c-handover.md)。
