# Lab5 进程复制、调度与生命周期

尚文轩（2412456）

## 1. 启动与调度

`proc_init()` 建立 `idleproc` 后，通过 `kernel_thread()` 和 `do_fork()` 创建 `initproc`。`schedule()` 从当前进程之后沿 `proc_list` 环形寻找 `PROC_RUNNABLE`，一圈无可运行进程时切到 `idleproc`。调度入口保存 SIE，并在进程恢复原调用栈后恢复进入时的中断状态，因此可从 `do_wait()` 的关中断区调用。

`proc_run()` 更新 `current`。地址空间变化时，将进程页表根的物理地址写入 `satp` 并执行 `sfence.vma`。`switch_to()` 保存和恢复 `ra`、`sp`、`s0`～`s11`，其中 `a0` 和 `a1` 分别接收前后两个 `context` 的地址。新进程由陈铭宇实现的 `copy_thread()` 设置首次 `ra=forkret`，从 `forkrets()` 进入通用 trap 返回路径；已经执行过的进程则恢复先前停在 `switch_to()` 的内核调用栈。

## 2. fork 与地址空间所有权

`do_fork()` 依次取得 PCB、私有内核栈、地址空间和首次 trapframe。资源齐备后才分配 PID、加入哈希与进程树，并唤醒子进程。`set_links()` 同时维护全局链表和进程计数。创建中途出错会回收已取得的资源，子进程在发布前对调度器不可见。

| 场景 | 地址空间 | 返回现场 |
| --- | --- | --- |
| 内核线程，父进程 `mm == NULL` | 使用启动页表 | 内核栈和 `kernel_thread_entry` |
| `CLONE_VM` 且父进程有 `mm` | 共享同一个 `mm` 与页表根，增加 `mm_count` | 私有内核栈和 trapframe |
| 普通用户 fork | 新 `mm`、新页表根与独立的 VMA；默认 COW，可清理重建为逐页复制 | 子进程继承用户 SP，`a0=0`；父进程收到子 PID |

`dup_mmap()` 先登记 VMA，再为该区域建立子页表项，空洞和栈保护页仍未映射。出错时 `exit_mmap()` 可根据完整登记的区间清除部分完成的映射和空页表目录。逐页复制保留权限并复制整页内容。`mm_count` 统计共享同一个地址空间的进程数，`Page.ref` 统计引用同一个物理页的映射数。

## 3. 退出、让出与终止

`do_exit()` 先切回启动页表，再减少地址空间引用，归零时回收映射、页表和 VMA。随后登记退出码与 `PROC_ZOMBIE`，唤醒处于 `WT_CHILD` 的父进程，并把子进程转交 `initproc`。已退出的孤儿也能唤醒正在等待的 `initproc`。最终由父进程在 `do_wait()` 中解除哈希和进程关系，释放僵尸的内核栈和 PCB。

`do_yield()` 设置 `need_resched`，从用户 trap 返回前交给调度器。轮转时间片为四个时钟 tick，耗尽后由 `sched_tick()` 设置同一标记，使 `spin` 中的忙循环能被抢占。`do_kill()` 标记 `PF_EXITING`，并唤醒处于可中断等待的目标。用户态返回前再次检查该标记，包括在一个调度周期内被其他进程标记的情况。`idleproc`、`initproc` 和无效目标由 `do_kill()` 拒绝。

## 4. 联合验证中的修复

- 教师脚本在 `readline` 处停机采集结果。评分构建在 `init` 完成回收后进入现有内核监视器，普通启动继续运行调度循环。
- `forktest` 首次能完成用户断言，但随后触发 `init` 的空闲页断言。SLOB 会留存完全空闲的堆页。现在空闲块仅在同一页内合并，整页空闲时从 SLOB 链表移除并交还 PMM。
- 真实耗尽测试暴露了 First-Fit 的尾部插入问题。向空闲链表尾部插入后应结束遍历，否则会再次处理刚插入的节点。初始化和释放路径都补齐了这一终止条件。
- 每个 tick 都轮转时，慢速 GDB 控制台会将不同进程的逐字符输出交织。采用固定四 tick 的轮转时间片，仍可通过 `spin` 验证抢占，也减少了频繁切换。教师原脚本的字符串匹配最终通过。

## 5. 验证

QEMU 6.2、OpenSBI 1.3、默认 128 MiB 下，COW 和逐页复制分别通过 `hello`、`exit`、`yield`、`spin`、`forktest`、`forktree`、`waitkill` 和 `c_lifecycle`。用户态用例检查了相邻页边界上的两向写入隔离、跨页 `waitpid` 输出、只读输出指针、重复等待、无效 kill、运行中与已退出孤儿的接管。内核侧用例检查 `CLONE_VM` 的可见性和引用计数，以及真实耗尽时的部分复制回滚。专项构建的物理空闲页均为 `31548 → 31548`。源码与运行日志见 [C 验证索引](../notes/lab5-c-handover.md)。

这个实验把进程实体、用户地址空间和物理页分别管理。它通过单 hart 的 trap 临界区和已有 `mm_lock` 完成当前同步，设备中断驱动、多核调度、跨核 TLB shootdown 与文件页缓存属于后续内核机制。
