# 本次采用的助教四段式规格

用户在扩展实施中提供了助教对 AI 协作实验的讲解。这里整理其含义与本组材料的对应关系，不伪造原始学生交互。

| 部分 | 需要说清楚 | 本组使用方式 |
|---|---|---|
| Prompt | 闭合任务、修改范围、操作及可验证输出 | 实际修改代码，不只展示草稿；保留教师测试、既有接口和工具包装器 |
| Rely | 最小、可信、与工程一致的依赖 | 页接口/对齐、设备树输入长度、真实ELF和satp，不堆砌无关代码 |
| Guarantee | 必须交付的接口清单 | 明确公开API、脚本、日志及规格，不将内部实现细节当作对外契约 |
| Specification | 前置条件、成功后状态、失败条件与无副作用要求 | 对齐、计数、恢复、不重叠、拒绝错误输入和明确的断言/返回值 |

助教强调需求分析、系统思维、人工验证和迭代能力。提示词粒度以可独立实现和验证的功能任务为单位，既不是“实现某函数”一句话，也不是把整个实验混成一段。规格描述需要满足什么，不能只给机械步骤；人工仍需阅读实际生成的代码并独立解释。

本次应用：

- [SLUB规格](../prompts/slub.md)：初始设计和测试规格在前，用户补充助教讲解后的四段式复核在后，保留真实时间顺序。
- [DTB规格](../prompts/dtb-memory.md)、[地址演示规格](../prompts/address-demo.md)：编码前已写入，按四段式约束实施。
- C 原Buddy的 [实现](../prompts/c-buddy.md) 和 [测试](../prompts/c-buddy-tests.md) 记录保留最初来源说明；可据代码用新格式复核，但不能改称当初学生已逐字输入。
- A 的初始化记录仍需本人从实际对话补齐；知道标准格式不等于知道其原始问题、人工修改与反馈。

实际迭代例：隔离Buddy测试范围修正；宿主gcc误选RISC-V as时明确本机binutils；GDB satp按uint64解释。成功/失败证据分别保留，不能用后写规格伪造全过程一次成功。各人仍须在答辩时不借助AI即时解释算法、接口和测试。
